## 1. Вступ

Метою навчальної практики було набути практичних навичок проєктування та розроблення клієнт-серверного вебзастосунку. Для виконання завдання розроблено вебсайт музичної школи «Мрія», який презентує навчальні напрями та надає відвідувачам змогу подати заявку на пробний урок.

Під час роботи опрацьовано структуру вебсторінок, компоненти інтерфейсу, адаптивне компонування, обмін даними між клієнтом і REST API та перевірку введених користувачем даних.

## 2. Постановка завдання

Проєкт має містити щонайменше чотири екрани: головну сторінку, каталог сутностей, сторінку деталей та сторінку з формою. Як основну сутність обрано курс музичної школи з пов’язаними відомостями про викладача. Головною бізнес-функцією є онлайн-запис на пробний урок.

Функціональні завдання:

- представити школу та її переваги на головній сторінці;
- відобразити курси й надати можливість фільтрації каталогу;
- показати опис, викладача, тривалість, вартість та розклад обраного курсу;
- створити форму запису на пробний урок;
- перевіряти дані форми на клієнті та сервері;
- забезпечити навігацію, адаптивність і базову доступність.

## 3. Проєктування та дизайн

Визначено п’ять маршрутів: `/` — головна, `/courses` — каталог, `/courses/:id` — деталі курсу, `/booking` — запис, `/contacts` — контакти. Дизайн побудовано на теплому світлому тлі, сливових акцентах і м’яких пастельних кольорах карток. Типографіка поєднує чіткий sans-serif для навігації та курсивний serif для емоційних акцентів.

Для вузьких екранів навігація перетворюється на меню-кнопку, картки й форма переходять в одну колонку, а декоративні елементи не перекривають інтерактивний вміст. Детальна специфікація wireframe, палітри, компонентів та макетів desktop/mobile наведена у файлі [design-spec.md](./design-spec.md).

## 4. Реалізація

Клієнтську частину реалізовано на React із Vite та React Router. Серверну частину реалізовано на Node.js і Express. Відомості про курси надаються власним REST API:

| Метод і маршрут | Результат |
|---|---|
| `GET /api/courses` | Список напрямів |
| `GET /api/courses/:id` | Деталі напряму або відповідь 404 |
| `POST /api/trial-lessons` | Перевірка заявки та відповідь 201 або 400 |

Клієнтська перевірка відображає помилки біля полів. Сервер повторно перевіряє ім’я, електронну адресу, номер телефону, наявність курсу, дату та довжину коментаря; результат надсилається у форматі JSON. Для демонстрації заявки тимчасово зберігаються в пам’яті процесу, тому не зберігаються після його перезапуску. Для реального використання необхідно під’єднати постійну базу даних і визначити процедуру обробки персональних даних.

Адаптивні стилі передбачають mobile-first поведінку та контрольні ширини 360, 768 і 1280 px. Застосовано семантичні елементи HTML, підписи до полів, стани фокусу, текстові повідомлення валідації, skip-link і підтримку системного налаштування зменшення анімації.

## 5. Тестування

Для API підготовлено автоматизовані тести на отримання каталогу, відповідь 404 для невідомого курсу, відхилення некоректної заявки та приймання коректної заявки. Команди запуску:

```bash
npm install
npm test
npm run build
```

**Фактичний результат запуску тестів і збірки:** `npm test` — 4 тести успішні, 0 помилок; `npm run build` — production-збірка завершилася успішно.  
**Перевірка адаптивності:** маршрути головної, каталогу, деталей курсу, запису й контактів перевірено при ширинах 360, 768 і 1280 px; горизонтального переповнення не виявлено. Каталог і фільтр перевірено у браузері; форма відхиляє порожні дані та приймає коректну тестову заявку; мобільне меню відкривається й навігує до контактів.

## 6. Використання AI-інструментів

Під час підготовки навчального проєкту використано AI-асистента Copilot SDK у VS Code для допомоги зі структурою React-застосунку, компонентами й стилями, чернетками тексту інтерфейсу та звіту, а також перевіркою API. Усі фрагменти перед здачею необхідно перечитати, перевірити та бути готовою пояснити їх роботу під час захисту. Студентці потрібно вказати інші AI-інструменти, якщо вона додатково їх використовувала.

## 7. Результати та висновки

У результаті створено адаптивний вебзастосунок музичної школи з головною сторінкою, каталогом, деталями курсу, контактами й формою запису. Клієнт отримує дані з Node.js REST API, а сервер перевіряє заявки незалежно від клієнтської валідації. Проєкт містить інструкцію запуску та автоматизовані API-тести, які пройшли локально.

Під час виконання завдання набуто навичок побудови маршрутизації у React, організації обміну даними із сервером, створення адаптивних компонентів і перевірки форм. До фінальної здачі слід завершити зовнішні етапи: створити публічний GitHub-репозиторій і поступово вести історію змістовних комітів у форматі `feat:`, `fix:`, `docs:`, опублікувати макети у Figma, налаштувати deploy із гілки `main`, перевірити Lighthouse та додати справжні скриншоти й посилання.
